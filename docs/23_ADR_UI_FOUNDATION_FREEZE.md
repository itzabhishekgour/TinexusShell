# Architecture Decision Record (ADR): UI Foundation Freeze (Engineering Gate 1)

## Status
**FROZEN** (Gate 1 Validation Passed)

## Context
As we transition from the lower-level systems engineering phase (`libtxui 0.1` - Windowing, Pixman Rendering, Wayland integration) into the higher-level interactive UI layer (`libtxui 0.2` - Layout, Hit Testing, Widgets), we need absolute confidence in the foundational architecture. 

A "leaky abstraction" or non-deterministic bug in the core layout/rendering engine will multiply exponentially as the widget hierarchy grows into the thousands of nodes. Therefore, before proceeding to `Phase 4.4` (Hit Testing), we are establishing **Engineering Gate 1** to freeze the core public API and validate algorithmic complexity, deterministic behavior, and memory lifecycle guarantees.

## Decisions

### 1. The Three-Phase Pipeline
We formally adopt and freeze the **Measure → Layout → Paint** unidirectional pipeline.
- **Measure**: Widgets compute their `desired_size` based on parent `Constraints`. (Bottom-up).
- **Layout**: Parents assign `frame` (x, y, width, height) to children. (Top-down).
- **Paint**: Widgets record visual operations into a stateless `CommandBuffer`. (Top-down).

### 2. Pull-Based Rendering Model
Widgets do **not** retain surfaces or pixels. They only retain logical state and emit a `CommandBuffer` on demand. The Wayland event loop dictates when a frame is needed, "pulling" a frame from the UI root rather than widgets "pushing" pixels randomly.

### 3. Widget Tree Ownership Model
- **Downward Ownership**: Parents own children via `Ref<Widget>` (intrusive ref-counted pointers). 
- **Upward Pointers**: Children retain non-owning raw pointers (`Widget* m_parent`) to their parent to prevent reference cycles.
- **Tree Invariants**: A widget may only have one parent at a time. It cannot be an ancestor of itself. Destruction of the root deterministically cascades and destroys the entire subtree.

### 4. Determinism Contract
- **Layout Determinism**: Given the same constraints and widget properties, 1,000 passes of `measure()` and `layout()` MUST result in the exact same FNV-1a hash of coordinates.
- **Paint Determinism**: The `CommandBuffer` byte stream generated by a static tree MUST hash identically across 1,000 passes.

### 5. RenderTarget Abstraction Contract
The UI toolkit `libtxui` must never directly reference `Wayland` types in its common logic. It relies exclusively on the `RenderTarget` interface (`pixman_image_t* back_buffer()`, `present()`). The underlying double-buffering and SHM allocations are decoupled implementation details.

### 6. Event Delivery Model (Reserved for Phase 4.4)
The foundation sets the stage for an event routing system that propagates Wayland inputs:
1. Hit-Test based on layout frames.
2. Tunneling (Capture phase) -> Top-Down.
3. Bubbling (Dispatch phase) -> Bottom-Up.

## Consequences
- The public APIs of `Widget`, `Window`, `Painter`, `RenderTarget`, `Constraints`, `FlexLayout`, `Padding`, `Event`, and `CommandBuffer` are now **FROZEN**.
- Any future modifications to these headers require a major version bump or an architectural review.
- We have introduced `public_api.sha256` which will cause CI to fail if these headers drift without authorization.
